## Идеи, адаптированные в блоке 3

- Коммит форка `eafddd9`: не навязывать основному API strict schema. В VNE режим Auto использует инструкции для основного подключения и Connection Manager. Явный JSON Schema оставлен для поддерживающих его подключений; JSON mode доступен прямому Custom API. Для main используется `returnInvalid`, чтобы Tavern не скрывал неверный ответ за пустой обёрткой.
- Не отправлять пустой результат на исправление. Проверяются пустой текст, markdown-обёртка, `{}`, `[]`, `null` и пустое поле `options`.

Реализация адаптирована к нашей отмене и фиксации контекста. Дополнительно введены общий валидатор и единый бюджет дополнительных запросов (по умолчанию 3, диапазон 0–5). Auto для Custom API снижает формат Schema → JSON mode → инструкции только после HTTP 400/422 с указанием неподдерживаемого формата. Ошибки авторизации, квоты и обычные ошибки параметров не запускают такой переход. Ответы старого формата-массива продолжают приниматься.

## Полезные кандидаты для следующих этапов

- Проверки snapshot v2, сводка содержимого и более удобный импорт: сопоставить с блоком 5.1. Не переносить формат целиком: события привязаны к индексам сообщений и свайпам; в другом чате эти индексы могут обозначать другие сцены. Нужно определить проверяемую идентичность источника и сохранить наш replay событий после импорта.
- Toolbar/popups HUD и пагинация: отдельно оценить на длинном списке персонажей и узком экране. Это изменение интерфейса, не исправление совместимости API.
- Независимое отключение генератора, редактор памяти/черт/журнала и пользовательские промпты: возможный следующий план после текущих блоков. Редактирование игровых данных требует понятных правил пересчёта и отмены.

## Почему нет полного merge

Форк значительно меняет HUD и социальную модель вместе с API-правками. Перенос всего набора смешал бы согласованный план с новыми правилами хранения и интерфейсом. Наша отмена, тайм-ауты, безопасная диагностика и Connection Manager уже реализованы отдельно. Нужные идеи переносятся небольшими проверяемыми изменениями.

## Ограничения проверки

Транспорт и DOM проверены на подменённых границах с реальными модулями VNE. Живые провайдеры и браузер не проверялись. Основное подключение и Connection Manager не предоставляют здесь одинаковую структурированную диагностику отказов: Auto поэтому не экспериментирует со схемой на этих маршрутах. Метаданные обрезанного ответа проверяются там, где доступны — в прямом Custom API.
